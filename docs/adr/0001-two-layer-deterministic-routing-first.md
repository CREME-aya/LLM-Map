# ADR-0001: 二層制御と決定論的経路探索の優先

- **ステータス**: Accepted
- **日付**: 2026-11-20

## コンテキスト
本アプリは LLM / SLM を活用した地図アプリであるが、経路や座標・道路規制・TBT 案内をモデルに直接生成させると空間ハルシネーションや通行不可誘導を招き、走行中の安全性と信頼性が崩壊する。また、毎回すべての探索で SLM を動かすとミドルレンジ Android 端末で遅延と発熱が過大になる。

## 決定
経路選定と運転しやすさ評価を明確な二層構造とし、日常制御は **100% 決定論的なロジック比較（L1/L2）** で完結させ、**LLM / SLM（L3）は個人最適化や自然文制約を「検証済みの型付き差分（`PersonalRoutingOverride`）」へ変換する必要時のみ起動** する。

- **Phase 1**: Valhalla 標準探索＋既存コストバリアント＋決定論的 `through` 経由点探索から得た合法候補を、Rust コアが 3 軸（所要時間差・対向横断右折・狭路距離）で採点・比較する。
- **Phase 2 移行境界**: Phase 1 の枠組みを保ったまま、`RoutingEngine` の型付き `Capability` と `CostPolicyVersion` を介して Valhalla C++ `AutoCost` の内部コスト改造（forward/reverse・ショートカット集約一致検証）へ拡張する。

## 検討した代替案
- **初期から C++ `AutoCost` 改造を必須化する案**: Phase 1 の PoC・テスト負担が増大し、ショートカット辺の二重加算バグ等の検証に時間を要するため、Phase 2 への境界設計だけ先行し Phase 1 は標準候補＋経由点比較を採用した。
- **常時 SLM で全経路を評価・説明する案**: ミドルレンジ機のメモリ・熱バジェットを超過し、確定経路の再現性も損なわれるため却下。

## 影響とトレードオフ
- **利点**: SLM なし（Tier 0）でも全基本機能が確実に成立し、同じ入力・版に対する採点再現率 100% と Safety Gate による迂回上限保証が可能になる。
- **制約**: Phase 1 では Valhalla 標準探索が生成した候補集合の範囲内での比較（「比較候補内で改善」）となるため、複雑な局所迂回の網羅性は Phase 2 の `AutoCost` 拡張で補う。

## 再評価条件
- PoC Gate 3（40 OD 監査）において、標準候補＋`through` 経由点のみでは目標値（代替あり集合で対向横断右折 30% 減・狭路 20% 減）を達成できない場合、Phase 1 内での限定的な `AutoCost` 前倒し導入を検討する。
