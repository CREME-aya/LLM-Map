# ADR-0006: Phase 1 GMS 非依存と歴史解説割り込み仕様

- **ステータス**: Accepted
- **日付**: 2026-11-20

## コンテキスト
1. 位置情報取得に Google Play Services (`FusedLocationProviderClient` / `ActivityRecognition`) を必須とするか、標準 API (`LocationManager`) にするかが論点となった。後から GMS を抜くコストは高いが、抽象化しておけば後から足すコストは低い。
2. 走行中の歴史解説は長距離ドライブで有効化確認を行うが、P0/P1 ナビ音声による割り込み後の挙動（再開するか打ち切るか）について安全・TTS 実機遅延・体験価値のバランスを決める必要があった。

## 決定
1. **Phase 1 は GMS 非依存**: 位置情報は `LocationSource` インターフェースの後ろに隠蔽し、OS 標準の `LocationManager (GPS_PROVIDER)` ＋テスト用 `ReplaySource` を標準とする。走行判定・トンネル推測は速度ヒステリシスと Rust マップマッチングで担い、`ActivityRecognition` にも依存しない。
2. **歴史解説の割り込み方針（折衷仕様）**:
   - 長距離・旅行判定時のみ出発前に 1 回確認（既定 OFF）。
   - パックに事前格納した **短文（≤ 12 秒）** と **1 文要約（4〜7 秒）** のうち、**発話開始前** の安全窓（次の P1 締切 − TTS 準備 − 5 秒）に収まる方を選択する。
   - **発話開始後** に P0/P1 ナビ案内等で割り込まれた場合は即時消音し、**Phase 1 標準では再開せず「あとで見る」リスト（旅履歴）へ保存して打ち切る**。

## 検討した代替案
- **最初から GMS 必須にする案**: 屋外車載中心では `LocationManager` で成立しやすく、de-Googled 端末や別配布チャネルの選択肢を早期に閉じる必要がないため保留。
- **Phase 1 から割り込み後の自動要約再開を必須にする案**: 市街地連続分岐で通過済み地点の話が再開される違和感や OEM TTS の停止コールバック遅延リスクが高いため、Phase 2「じっくり」モードの任意機能へ分離。

## 影響とトレードオフ
- **利点**: GMS 非搭載端末互換を保ちつつ、P0/P1 ナビ案内の遅延・欠落ゼロ（消音 ≤ 250 ms / 出音 ≤ 500 ms）を最優先で達成しやすい。
- **制約**: 都市部高架下・ビル街での `LocationManager` 捕捉精度・復帰速度を PoC で監視し、不足時は Play 版フレーバー限定で `location-gms` モジュールを追加する。

## 再評価条件
- 都市部実走・GPX 比較テストで `LocationManager` 単独ではトンネル復帰や測位遅延が合格基準を満たさない場合、`LocationSource` 実装として Play フレーバー専用の GMS アダプターを追加する。
