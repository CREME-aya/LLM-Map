# 05. 推論 Tier 動的切替・音声調停・長距離歴史解説

> **対象フェーズ**: Phase 1（Tier 0/1 ＋ 試験的 Tier 2、簡潔歴史）〜 Phase 2（LiteRT-LM NPU、じっくり歴史）
> **関連 ADR**: [ADR-0004](../adr/0004-isolated-inference-and-hardware-tiers.md), [ADR-0006](../adr/0006-gms-optional-and-history-preemption.md), [ADR-0007](../adr/0007-l3-one-line-command-and-confirm-separation.md), [ADR-0008](../adr/0008-dc-tick-single-event-entry.md)

---

## 1. Rust コアと SLM 推論バックエンドの責務分離

- **誤解の防止**: 狭い純粋 Rust コア（経路採点・`ManeuverHorizon`・音声スケジューラ）は **CPU でマイクロ秒〜ミリ秒動作する決定論処理** であり、GPU や NPU は一切必要としません。
- **GPU / NPU 動的切替の対象**: ハードウェアアクセラレータの有無に応じて切り替える対象は、Kotlin 推論コントローラ配下の **`SlmEngine`（ローカル SLM 推論バックエンド）のみ** です。SLM が利用できない端末・状況でも Tier 0 として通常ナビと 3 手先表示・定型音声は 100% 機能します。

---

## 2. 別プロセス隔離（`:inference`）と障害保護設計

ミドルレンジや多機種混在環境での Vulkan / OpenCL / NPU ベンダー固有ドライバクラッシュから **ナビ本体（地図・Valhalla・TBT 音声）を完全に守る** ため、SLM 推論は非公開の別プロセスバインドサービスへ隔離します。

- **プロセス境界**: Android Manifest 上で `android:process=":inference"`, `android:exported="false"` として定義（同一 UID 内での障害隔離であり、モデルファイルは内部領域で安全参照）。
- **やり取りするデータ**: 起動コマンド・版付き Intent 差分 JSON・短い事実カードキー等のみ。ナビ本体が `ManeuverHorizon`・Valhalla・TTS を常時掌握。
- **クラッシュ・ハング検知と自動降格**:
  1. **起動前マーカー**: メインプロセスが初期化試行マーカーをディスクへ書き出してから `:inference` のバックエンドを初期化し、成功したら消去。
  2. **障害検知**: Binder death、native abort、バックエンドエラー、応答タイムアウト（初期値 2.5 秒打切り）を個別検知。ハングしたプロセスは終了・再生成可能とする。
  3. **失敗組合せの記録**: `SoC / ドライバ / OS / アプリ / ランタイム / モデル版` の組合せでクラッシュ・タイムアウトを検知した場合、その端末で問題バックエンドをブラックリスト化し、次回以降は即座に安全な下位 Tier（CPU または Tier 0）で起動。
  4. **カーネル級障害への備え**: 別プロセスでも防げないカーネル/端末全体リセットに備え、Tier 2（GPU/NPU）は **実機 allowlist＋設定からの強制撤回** 前提で開放。

## 3. 機種スペック適応 3 段階 Tier 制御

起動時のハードウェア情報（RAM、CPU NEON `dotprod`/`i8mm`、Vulkan 対応、SoC NPU 情報、熱・メモリ状態）と、**ナビ中ではない停車時にユーザー同意のもと行う約 10 秒のマイクロセルフテスト** により Tier を決定します。

| Tier | ユーザー向け表記 | 有効条件 | 採用エンジン & モデル | できること / 制御仕様 |
|---|---|---|---|---|
| **Tier 0** | AIアシスト：オフ（決定論） | SLM 未導入、ユーザー OFF、RAM 不足（目安 `< 4.5 GB`）、ADPF `SEVERE`、異常発生時 | 推論なし（文法照合＋定型ボタン＋L1/L2） | 通常ナビ、3 手先パネル、回避提案、定型音声コマンドを 100% 維持 |
| **Tier 1** *(ミドル機既定)* | AIアシスト：標準 | arm64、空きメモリ確保、0.5B 実機基準合格（RAM 6〜8 GB 帯想定） | **`llama.cpp` C API (CPU NEON)** ＋ **`Qwen2.5-0.5B-Instruct` Q4_K_M** (491 MB, Apache-2.0) ＋ **GBNF** | CPU 2 スレッド、1 件逐次、context 768〜1024、出力 ≤32 tokens、2.5 秒打切り、**利用後 2 分でウォーム解放** |
| **Tier 2** *(ハイエンド)* | AIアシスト：高速 | 対象 SoC/GPU/NPU 組合せが検証済み＋セルフテストで CPU 比 p95 20% 以上高速（またはエネルギー 15% 減）＋描画フレーム悪化なし | ・先行 GPU：`llama.cpp` Vulkan GPU（同一 GGUF）<br>・NPU（Phase 2〜）：`LiteRT-LM` 別アダプター（SoC 別 `.litertlm`＋配布可能ランタイム） | Tier 1 の高速実行＋1.5B モデルの個別評価対象。**走行中は昇格せず、降格（縮退）のみ実行** |

*(注意: Google 公式の LiteRT-LM 測定でも Gemma-4-E4B 単独で 3.65 GB を消費するため、4B クラスをナビと同時稼働する前提は置かず、0.5B Q4 を共通ベースラインとします。)*

### 3.1 ADPF Thermal とメモリ圧による自動縮退ルール
`PowerManager.getCurrentThermalStatus()`（主）と headroom（補助・10 秒以上間隔）、および `ActivityManager.MemoryInfo.lowMemory` を監視し、走行中は即時に安全側へ縮退します。

- **熱状態の受け渡し**: Kotlin は熱状態を `dc_tick` の `thermal{status}` イベント（[ADR-0008](../adr/0008-dc-tick-single-event-entry.md)）として渡す。`status` は `none | light | moderate | severe | critical | emergency | shutdown` の 7 段階で、**Rust 側で `critical` 以上（critical / emergency / shutdown）を 1 つの状態として扱う**。
- **未確認（Gate 0 で確認）**: 7 段階であること、および `THERMAL_STATUS_*` 定数との対応は記憶ベースであり、Gate 0 で実際の定数を確認する。

| 状態検知 | 縮退アクション |
|---|---|
| **ADPF `MODERATE`** | P3 歴史解説と先読み停止。Tier 2 は Tier 1 (CPU) へ降格、重い処理と推論の並列を禁止 |
| **ADPF `SEVERE` 以上 / `lowMemory`** | 進行中推論の即時取消 → `:inference` モデル・KV キャッシュ解放 → **Tier 0 へ降格**（ナビ・地図・TTS は継続） |
| **ADPF `CRITICAL` 以上**（critical / emergency / shutdown を 1 つに扱う） | 地図描画フレーム・情報更新を最小化し、基本誘導の継続のみ死守 |
| **復帰条件** | 熱状態が正常方向へ **60 秒以上安定** し、かつ利用者が明示的に再要求した場合のみ再評価（古い保留命令は破棄） |

### 3.2 遅延予算とコールド経路
数値はすべて暫定初期値（PoC で校正）で、正本は [07 §1](07-parameters-and-poc-gates.md)。

| 区分 | 予算・規則 |
|---|---|
| **温時（モデル常駐）** | **p95 ≤ 2.0 s**。内訳は ASR 終了→ **0.6 s** / SLM **1.2 s** / 検証＋再採点 **0.2 s** |
| **SLM 打切り** | **2.5 s** は上限として残す。打切り時は定型チップへ切り替える |
| **コールド（モデル未常駐）** | ASR ボタン押下と同時にモデルを **並行プリロード**。**0.5 s 以内** に Tier 0 の文法照合候補を先行提示し、SLM 結果が **3 s 以内** に出たときだけ追補、それ以外は破棄 |
| **コールド結果の提示条件** | `route_key` が現行一致し、かつ確認画面が有効なときだけ提示。期限切れ・取消・経路更新後に届いた結果は破棄。判定は `dc_tick`（[ADR-0008](../adr/0008-dc-tick-single-event-entry.md)）で行う |
| **定型語の SLM バイパス** | 「はい / いいえ / やめて / キャンセル」等の定型語は SLM を通さず、**Rust の辞書照合** で処理（**< 50 ms**） |

## 4. 走行中 SLM の許可範囲と厳禁事項

### 4.1 走行中軽量 SLM が担当する 5 つの制御タスク
1. **曖昧な音声要望の制約変換**: 「さっきみたいな右折もうやだ」「裏道やめて」→ **1 行命令コード**（`OVR` / `CXL` / `WHY` / `BMK` / `YES` / `NO` / `NOOP`、GBNF 正本は [03 §4.1](03-routing-and-two-layer-control.md)）→ Rust `dc_validate_override` で解析・Safety Gate（[03 §4.2](03-routing-and-two-layer-control.md)）経由で候補再採点・確認提示。
2. **左側進入しやすい寄り道解釈**: 「入りやすいコンビニ寄りたい」→ 左折進入・最小迂回での施設検索条件変換（Phase 2）。
3. **「なんでこの道？」の 1 文説明**: SLM が出すのは **`WHY` の分類トークンのみ**。説明文は `RouteComparison` の確定値（回避した無信号右折数・狭路距離など）から **Kotlin のテンプレートで生成** し、SLM は文面を作らない。
4. **言い直し・直前取消の吸収**: 「やっぱ今のなし」「さっきの方で」を文脈から直前提案の取消へマップ。
5. **長距離時の簡易状態確認補助**: 「あとで詳しく」ブックマーク保存等の意図分類。

- **確定入力の分離**（[ADR-0007](../adr/0007-l3-one-line-command-and-confirm-separation.md)）: 経路を確定する入口は **Rust 辞書照合で一致した `dict_norm`（辞書 yes）** と **`user_tap`** の 2 つだけ。SLM が `YES` を出しても確定せず、再確認を促すだけにとどめる。

### 4.2 走行中 SLM に絶対やらせてはいけない 7 事項
1. 座標・経路形状・TBT 案内文の直接生成。
2. ユーザーの明示同意なしの自動ルート変更（明示同意として扱うのは辞書照合の yes と `user_tap` のみ。SLM の `YES` は同意に数えない。§4.1 参照）。
3. 「この右折は安全です」といった安全の保証発言。
4. 歴史的事実・年号・営業時間のその場生成（ハルシネーション源）。
5. 15 秒超の長文発話や往復雑談。
6. **P0 / P1 ナビ案内音声スレッドへの介在**（推論は別プロセス非同期、タイムアウト時は即破棄）。
7. 画面への長文テキスト表示。

## 5. 音声優先度スケジューラ（`P0 > P1 > P2 > P3`）

単一の Rust 音声スケジューラが全発話要求を **`utterance_token = { route_key, event_id, generation }`** で管理し、Kotlin の単一 TTS キュー管理層へ指示します。

| 優先度 | 種別 | 挙動・割込み規則 |
|---|---|---|
| **P0** | 案内継続に必要な緊急状態・危険注意 | 他すべての音声を即座に中断して再生（未検証の危険予測は含めない） |
| **P1** | 右左折・分岐・再探索案内（ManeuverHorizon 連動） | P2 / P3 を即時中断して割り込む。連続分岐の結合案内は `HorizonEntry.group_id`（[04 §2.1](04-maneuver-horizon-and-hmi.md)）が同じ操作に限り、音声側で距離・秒数の閾値を持たない。切迫時・鮮度切れは溜めずに破棄 |
| **P2** | 許可済み音声コマンド応答・回避提案予告 | 次の P1 案内を絶対に妨げない短文かつ安全窓内のみで発話 |
| **P3** | 長距離同意済みの歴史・地名解説 | 安全窓（§6-2）に収まる時のみ開始。P0/P1 発火・通話・逸脱・停止操作で即時消音 |

- **TTS 実装上の安全ルール**: Android `TextToSpeech` の `stop()` / `QUEUE_FLUSH` の `onStop` コールバック到着を待ってから次の P1 を開始する実装は OEM 端末ごとの遅延が大きいため**禁止**。古い世代のコールバックは無視し、実測で **実効消音 p95 ≤ 250 ms・予定から P1 出音 p95 ≤ 500 ms** を計測（満たせない OEM 端末は P3 を無効化して P1 を死守）。
- **他音声との共存**: `AudioFocusRequest`（`AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK` 等）および通話状態の監視を組み込み、着信・通話中は P2/P3 を即抑止します。
- **オンデバイス ASR**: マイク常時待機は行わず、画面大ボタン（76 dp+）または Bluetooth ステアリングボタン押下時のみ Android `createOnDeviceSpeechRecognizer` を 1 回だけ起動（非対応機種・熱縮退時は定型ボタン操作へ縮退、無断クラウド送信禁止）。
- **ASR ログ**: ログに発話の生文字列は残さず、`text_class`（`dict` / `natural`）と辞書 ID のみを記録する（原文は評価ハーネスで明示的に有効化したときのみ）。

## 6. 長距離トリガーと歴史解説割り込み仕様

### 6.1 旅判定スコア（日常の邪魔をしない条件）
ルート確定時に端末内で計算し、閾値（初期値 **3 点以上**）を満たした場合のみ出発前比較画面下に C01 カードを 1 回提示します（**既定 OFF**、走行中の再探索時は確認しない）。

| 判定要素 | 条件例（初期値） | 点数 |
|---|---|---:|
| 経路距離 | 80 km 以上（150 km 以上で +3） | +2 / +3 |
| 予測所要時間 | 60〜75 分以上 | +2 |
| 高速道路区間 | 全長の 50% 以上 | +1 |
| 目的地種別 | 観光地・史跡・城・道の駅・宿泊施設 | +2 |
| 日常生活圏外 | 端末内の普段走行エリア外 | +2 |
| 沿線歴史密度 | パック内の歴史スポット密度高 | +1 |
| 過去の拒否履歴 | 類似移動で直近「つけない」を選択 | -3 |

### 6.2 歴史解説の再生制御と割り込み後挙動（最終折衷仕様）
```text
Eligible ──▶ Pending ──▶ Speaking ──▶ Completed
                │           └──────▶ Interrupted (Phase 1標準：同地点の再開なし・旅履歴保存)
                └──────────────────▶ Expired (回廊外・30秒超・停止操作)
```
1. **開始前安全窓チェック**:
   - `ManeuverHorizon` が `tracking` であり、複雑窓外・経路回廊内・他音声なし・熱縮退なし・方位/精度良好のときだけ候補評価。
   - 歴史パック内には出典付きの **短文（約 12 秒上限）** と **1 文要約（約 4〜7 秒）** の 2 版を事前格納。
   - `利用可能時間 = min(次の P1 締切, 複雑窓開始) - 推定 TTS 準備時間 - 安全余裕 5 秒`。`複雑窓開始` は `ManeuverHorizon.next_complex_window.start_monotonic_ms`（決め方は [04 §2.2](04-maneuver-horizon-and-hmi.md)）。`推定 TTS 準備時間` は Rust では測れないため入力として受け取る（Kotlin の実測値を渡すか固定値を設定で渡すかは未決。Gate 4 の TTS 実測後に決める）。開始前にこの枠へ収まる版を選択し、両方収まらなければ開始せず待機（同一 POI は 1 旅程 1 回、開始間隔は **最短 5 分**）。
2. **割り込み後挙動**:
   - **Phase 1 標準（「簡潔」モード）**: 発話開始後に P0/P1 ナビ案内等が入った場合は即座に停止し、**同じ地点の断片・再開は行わず「あとで見る」リストへ自動保存**（現在地と解説のズレ・TTS キュー複雑化をゼロにする）。
   - **Phase 2 オプション（「じっくり」モード）**: 高速道路など静かな長距離区間向けに設定で選択可能とし、再生進捗 50%（または 40%）未満かつ短時間内に次の空白が確保できた場合のみ事前生成したつなぎ 1 文で再開。
