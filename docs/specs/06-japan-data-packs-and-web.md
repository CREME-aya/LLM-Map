# 06. 日本全国データパック配布と Web 補完仕様

> **対象フェーズ**: Phase 1（全国固定版＋Web ルート閲覧・共有）〜 Phase 2（Web 計画・日記拡充）
> **関連 ADR**: [ADR-0003](../adr/0003-valhalla-on-device-and-japan-packs.md)

## 1. 日本全国 47 都道府県一括生成パイプライン

「最初から日本全国 47 都道府県に対応」しつつ県境跨ぎや長距離移動を破綻させないため、都道府県ごとに個別グラフをビルドせず、**固定版の日本全国データソースから一括生成した単一バージョン（`graph_version`）を、配布単位（全国概要＋8 地方・47 都道府県＋回廊チャンク）へ分割配布** します。

### 1.1 データソースと権利・ライセンス整理

| ソース | 用途 | 権利・帰属・制約ルール |
|---|---|---|
| **OpenStreetMap (Geofabrik Japan PBF)**<br>*(参考実測: `japan-261112.osm.pbf` = 2,574,069,427 bytes)* | 道路網・Valhalla グラフ・Vector Tile・`historic` 場所発見 | **ODbL**。アプリ内およびオフライン表示に OSM 帰属表示を常設。OSMF 公開標準タイルサーバからの一括取得・流用は厳禁とし、自前生成 PMTiles を使用。 |
| **デジタル庁 アドレス・ベース・レジストリ (ABR)** | 日本の町字・住所検索インデックス（独立 SQLite） | 出典別 DB として保持。試験公開データの地域可用性に従い、町字代表点は **精度表示＋地図ピン確認** とし、車両入口の推定には使わない。 |
| **文化庁文化財・自治体オープンデータ** | 日本国内の文化財・史跡の位置・事実ベース | 出典 URL・取得日・許諾条件をレコード単位で保持し、公開入口と私有地を区別。 |
| **Wikidata / 日本語 Wikipedia ダンプ** | 歴史・地名由来の出典付き短文（独立 SQLite） | Wikidata 構造化データは **CC0**、Wikipedia 本文を再利用する場合は **CC BY-SA 4.0** の帰属・版 ID・改変表示・継承条件を自動生成メタデータへ組み込む（画像は個別確認・原則 Phase 1 非同梱）。 |

### 1.2 成果物構成と初期容量見積もり（設計値）

*(注: 下表は Geofabrik 日本 PBF 約 2.57 GB をもとにした初期設計見積もりであり、PoC Gate 2 にて実生成サイズを実測校正します。)*

| 成果物 | 全国配信サイズ見積（十進） | 端末配置タイミング・備考 |
|---|---:|---|
| **全国概要 PMTiles (`z0–9`) + glyph/sprite** | 30–70 MB (+10–30 MB) | 初回案内前（日本語フォント・地図スタイル同梱） |
| **詳細 PMTiles (`z10–14`)** | 1.2–2.2 GB（全国計） | 地方/都道府県選択および経路回廊単位で DL |
| **Valhalla 幹線階層 (`L0/L1`)** | 100–250 MB（全国計） | 初回案内前（4 度 / 1 度タイル） |
| **Valhalla 詳細階層 (`L2` 圧縮配信) + 同版属性 sidecar** | 1.6–3.8 GB（全国計） | 現在地・目的地・経路回廊単位でオンデマンド DL（展開後 1.3〜2 倍想定） |
| **ABR 由来住所 SQLite** | 全国町字索引 40–90 MB<br>（詳細込 150–500 MB） | 全国町字索引は初回、詳細街区等は地域追加 |
| **歴史・地名 SQLite (`R*Tree` + `FTS5`)** | 50–100 MB（全国計 / 1 地方 5–20 MB） | 任意 DL（出典付き短文・要約・位置・時代のみ） |
| **走行中軽量 SLM (`Qwen2.5-0.5B-Instruct Q4_K_M`)** | 約 491 MB | **パックとは別枠の任意 DL**（Tier 1/2 利用希望時のみ、1.5B は比較用別枠） |

- **容量内訳（上限側）**: 地図系（PMTiles・Valhalla・sidecar・SQLite）の上限合計 **6.95 GB**、任意 DL の SLM（約 491 MB）を加えると **約 7.44 GB**。下記の見積上限 7.45 GB は **SLM 込み** の値です（数値は暫定見積で Gate 2 で実測校正）。R2 の容量判定（§3）に SLM を含めるかは置き場所で決まります（同じ R2 に置けば含める、R2 外から取得すれば含めない）。
- **合計規模感**: 全国成果物総計 **約 3.6〜7.45 GB**（SLM 込み、＋メタデータ）。初期の 1 地域導入は **230〜750 MB**（SLM 込み常用 **約 0.75〜1.5 GB**）。長距離旅行の回廊追加は **0.2〜1.0 GB** を仮置きし、DL 前にマニフェストから実サイズを明示します。

## 2. 県境・長距離横断・離島・再探索回廊設計

Valhalla の階層構造（`L0: 4°` / `L1: 1°` / `L2: 0.25°`。配布では L2 を 1 度セルにまとめる、§3）および GraphReader の性質上、上位階層（L0/L1）と両端の L2 だけでは、下位辺への遷移・ショートカット復元・規制解決・低階層のフェリー接続が欠落して不自然な経路や失敗が起きる場合があります。

1. **同一版の維持と需要タイル解決**:
   - 47 都道府県・8 地方はユーザー向けの選択 UI であり、配布グラフの物理単位は全国一括生成した同版の **Valhalla タイル ID**（県境の共有タイルは重複保存せず 1 度だけ保持）。
   - 接続中の出発前探索は端末上 **cache-first** とし、探索や復元に必須な途中のタイルが未取得であれば同版チャンクを追加取得します。
   - **不完全データの誠実分類**: マニフェスト上存在するタイルを取得できない場合は「探索完了」と表示せず、通信失敗／タイル不足／グラフ上到達不能を厳密に区別してエラー返却します。
2. **再探索回廊（Corridor）と機内モード出発ゲート**:
   - 出発確定前に、経路本体＋**経路周囲 1 セル（初期値）の再探索回廊タイル**＋詳細 PMTiles＋フェリー両端を端末へ導入し、通信を遮断した状態での再計算成立を出発準備条件とします。
   - 走行中に圏外のまま回廊外へ逸脱した場合は、古い誘導や嘘の再探索を止め、データ不足状態を明示して位置と保存済み経路表示へ退避します。
   - フェリーは車載可能タグの接続確認と運航時刻確認を別扱いとし、未確認の離島間接続を補完しません。

## 3. 無料公開を破綻させない配布インフラ（Cloudflare R2）

個人開発・基本無料で公開を継続するため、**静的オブジェクトストレージ（Cloudflare R2 Standard）** を中心に帯域・操作回数の上限管理を組み込みます。

- **R2 無料枠と警戒ライン**（公開料金体系前提）:
  - 直接 egress 無料、無料枠は保存 **10 GB-month**・Class A 100 万回/月・Class B **1,000 万回/月**。
  - **運用ガードレール**: 通常配置 **≤ 7.5 GB**（全国 1 版で判定）・版更新ピーク（新旧同時保管＝連続 2 版で判定）**≤ 9.0 GB**。どちらにも **同じ R2 に置く SLM とマニフェストを算入** し、R2 外から配布する SLM は除外します。新旧同時ピークは **アップロード前に判定** し、超過する場合の既定は **「現行版の配信を継続し、新版の公開を見送る」**（公開ジョブを停止する）。旧版配信期限の調整や段階化はこの停止中に行う対処とし、**別保管先の利用は連続する全国 2 版の実測後に検討** します。
  - **チャンク粒度**: HTTP オブジェクトは **目標 128 MB / 上限 256 MB** の静的チャンクに分割し、Class B リクエスト増加を抑制。
  - **保存単位**: Valhalla `L0/L1` は **全国共通**、`L2` は **固定 1 度セル** 単位で保存。1 度セルは **最大 4×4（16 枚）の 0.25° L2 タイル枠** をまとめて配る単位で、**実在するタイルだけを収録** します。圧縮後 256 MB を超えるセルは **固定境界で分割** します。都道府県は保存単位ではなく **取得時の索引**（どのセル/チャンクを取るかの対応表）として扱います。
  - **差分再利用**: チャンクは SHA-256 をキーとし、版更新時は **チャンク単位で同一ハッシュを再利用**（バイナリパッチは使わない）。
  - **属性 sidecar**: タイル単位の固定長バイナリとして同版グラフと一緒に配布し、manifest で `graph_version`・SHA-256 と組にします。バイナリ形式は `pipeline/packs/sidecar-format.md` を参照（[02 §1](02-architecture-and-stack.md)）。
  - **（検討候補）SLM の取得元**: SLM を R2 に置かず、配布元の固定リビジョンから取得して SHA-256 照合する案があります（未決事項ではなく検討候補）。
  - **リクエスト監視**: 月間 Class B 予測 **500 万回で警戒、800 万回で Web 高ズームタイルや自動先読みを制限** し、課金超過を未然防止（請求アラート併用）。
- **端末側の原子的配布プロトコル**:
  - **公開順序**: R2 上で全チャンクの検証が終わってから、署名付きマニフェストを **最後に** 切り替えます（マニフェストが未アップロードのチャンクを指す時間を作らない）。
  - 署名付き `manifest.json`（バージョン・タイル版・コミット・SHA-256・容量）＋ immutable ハッシュ URL ＋ HTTP Range/206 再開可能ダウンロード（200 応答時は安全再取得）＋ SHA-256 照合。
  - 端末内空き容量チェックは「未共有の展開後差分 ＋ 最大チャンク ＋ 予約余裕（＋更新時は旧世代保持）」で判定し、全ファイル検証完了後に同一ファイルシステム上で原子的に版切替（**端末は走行中の版を固定** し、走行中のルートは旧版へピン留め継続）。

## 4. Web 補完版とサーバ不要連携 (`exchange-v1`)

Web 版（`TypeScript + Vite + React + Tailwind CSS + Zod + MapLibre GL JS + pmtiles` → **Cloudflare Pages** 静的配信）は **「家で計画し、家で振り返る」補完ツール** とし、走行中ナビ・バックグラウンド測位・Pages 単一ファイル制限（25 MiB）を超える大容量配布は行いません。

### 4.1 画面スコープ（W01〜W04）
- **W01 計画プレビュー**: 目的地・経由地・運転しやすさプリセット設定と、R2 静的地図・回廊歴史スポットの確認（Phase 1 は計画作成＋Android 送信、Phase 2 で任意 BYOK 経路 API プレビュー追加）。
- **W02 プリセット編集**: L2「いつもの設定」（チップ・ハード/ソフト・重み）の作成・共有。
- **W03 共有受渡**: QR コード生成／リンク発行／`.drivediary` 読込。
- **W04 ドライブ日記ビューア**: Android から書き出した軌跡、避けた難所数、聞いた歴史チャプターの振り返り。

### 4.2 サーバ不要連携仕様（`exchange-v1`）
バックエンドサーバやアカウント管理を持たず（維持費・個人情報保管リスクを排除）、以下の 3 形式で Android ⇄ Web 間を連携します。

| 共有型 | 主な中身 |
|---|---|
| `IntentPreset` | `schema_version`, チップ ID 列, ハード/ソフト区別, 許容迂回, 重みプリセット |
| `TripPlan` | `schema_version`, 出発地・経由地・目的地（座標・名前）, プリセット参照, 旅モード設定（**経路形状ポリラインは送らず受信端末で同版再計算**） |
| `DriveDiary` | 走行軌跡 GPX ＋ 構造化 JSON（回避難所統計・再生/保存済み歴史チャプター ID） |

- **受け渡し媒体**:
  1. **URL フラグメント (`https://<domain>/p#<圧縮データ base64url>`) + QR コード**: 短いデータ（暫定上限 1,000 文字）用。フラグメント `#` 以降は HTTP サーバへ送信されない（[RFC 3986](https://www.rfc-editor.org/rfc/rfc3986.html#section-3.5)）一方、ブラウザ履歴やコピー・ページ内 JS から参照し得るため、**Web ページに第三者解析スクリプトを一切入れない** とともに、受渡画面に「含まれる出発地・行先」を明示確認させます。Android 側は `/.well-known/assetlinks.json` による App Links で受け取ります。
  2. **ファイル受渡 (`.drivediary` zip)**: 長大ルートや日記アーカイブ用（Google Drive 等で任意共有）。
- **厳格な境界検証**: 受信時は `schema_version`、WGS84 座標範囲、圧縮前/展開後サイズ上限、項目数、および **十進文字列の `u64` ID** を Zod（Web）および Rust（Android）で検証し、不正データは破棄。読み込み直後は既定で「プレビューのみ」とし、案内開始は明示操作でのみ許可。BYOK クラウドキーは絶対に共有ペイロードに含めず、各環境のローカルストレージ / Android Keystore に閉鎖します。
